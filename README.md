# VibeMonitor

Сервис мониторинга доступности сайтов с веб-интерфейсом, историей проверок, инцидентами,
Telegram-уведомлениями и публичной статус-страницей.

## Возможности

- Проверка доступности сайтов по HTTP/HTTPS (HEAD с fallback на GET)
- Индивидуальный интервал проверки для каждого сайта
- SQLite-хранилище: сайты, проверки, инциденты, пользователи, настройки
- Роли `admin` и `viewer`: просмотр доступен всем, изменения — только администраторам
- Пауза, ручная проверка и редактирование сайтов
- Теги, поиск, фильтры и сортировка в интерфейсе
- Графики задержки и аптайма за 24 часа, 7 и 30 дней (Chart.js, локальная копия)
- История инцидентов: подтверждение, заметки, длительность простоя
- Telegram-уведомления о недоступности и восстановлении, а также об истёкшем SSL
- Проверка срока действия SSL-сертификата (алерт только после истечения)
- Публичная страница `/status` для сайтов с включённым флагом «Публичный»
- Тёмная и светлая темы
- Язык интерфейса: русский по умолчанию, переключение на английский
- Эндпоинт `/healthz` для проверки состояния приложения
- Структурированные логи (text или JSON)

## Требования

- Docker
- Docker Compose

## Быстрый старт

```bash
git clone https://github.com/umaxk/vibesitemonitor
cd vibesitemonitor
cp .env.example .env
```

Обязательно измените `MONITOR_PASSWORD` в `.env`. При первом запуске создаётся
администратор с логином `admin` (или `MONITOR_ADMIN_USERNAME`) и этим паролем.
Пароль администратора можно позже изменить через интерфейс.

Запуск:

```bash
docker compose up -d --build
```

Интерфейс: `http://localhost:1485`

Публичная страница: `http://localhost:1485/status` (если включена)

## Переменные окружения

| Переменная | Описание | Обязательная |
|------------|----------|--------------|
| `MONITOR_PASSWORD` | Пароль первого администратора | Да, при первом запуске |
| `MONITOR_ADMIN_USERNAME` | Логин первого администратора (по умолчанию `admin`) | Нет |
| `MONITOR_ADMIN_PASSWORD` | Отдельный пароль первого администратора | Нет |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота для уведомлений | Нет |
| `MONITOR_SESSION_TTL_SECONDS` | Срок жизни сессии (по умолчанию 7 дней) | Нет |
| `MONITOR_COOKIE_SECURE` | Cookie только по HTTPS (`true`/`false`) | Нет |
| `MONITOR_DB_PATH` | Путь к SQLite-базе (по умолчанию `/app/data/monitor.db`) | Нет |
| `MONITOR_CONFIG_PATH` | Путь к legacy `config.json` для миграции | Нет |
| `MONITOR_LOG_PATH` | Путь к файлу логов | Нет |
| `LOG_FORMAT` | `text` или `json` | Нет |

## Telegram

1. Создайте бота через `@BotFather` и получите токен.
2. Укажите `TELEGRAM_BOT_TOKEN` в `.env` и перезапустите контейнер.
3. Откройте «Настройки → Уведомления», добавьте `chat_id` получателей.
4. Нажмите «Отправить тест».

Уведомления отправляются только при переходе сайта в состояние «недоступен»,
при восстановлении и при истечении SSL-сертификата. Повторных сообщений о том же
инциденте нет. SSL-уведомление не отправляется, если сайт уже недоступен.

## Пользователи и роли

- `admin` — полный доступ: сайты, настройки, получатели уведомлений, пользователи.
- `viewer` — просмотр сайтов, графиков и инцидентов.

Удалить последнего администратора или понизить его роль нельзя. Пользователи и
сессии хранятся в базе; старые cookie-сессии после обновления недействительны.

## Языки

Язык интерфейса — глобальная настройка проекта, задаётся администратором в
«Настройки → Общие → Язык интерфейса». Доступны русский (по умолчанию) и
английский. Настройка применяется к панели мониторинга, публичной статус-странице
и Telegram-уведомлениям без перезагрузки.

## Публичная статус-страница

Страница `/status` включается в «Настройки → Статус-страница». На ней показываются
только сайты с включённым флагом «Публичный». Технические тексты ошибок и заметки
к инцидентам на публичную страницу не выводятся.

## Данные и обновление

Всё состояние хранится в `./data`:

| Путь | Описание |
|------|----------|
| `data/monitor.db` | SQLite-база (основное хранилище) |
| `data/config.json` | Legacy-конфигурация, импортируется один раз при первом запуске |
| `data/monitor.log` | Файл логов |

При обновлении со старой версии перенесите `config.json` и `monitor.log` в `./data/`.
Сайты из legacy-конфигурации импортируются автоматически, если база ещё пуста.
Перед обновлением рекомендуется сделать резервную копию каталога `data/`.

Внутри контейнера процесс работает от непривилегированного пользователя `monitor`
(uid 1000). При старте entrypoint автоматически назначает владельцем каталога
`./data` пользователя `monitor`, поэтому bind-маунт должен быть записываемым
для root. Если каталог `./data` ранее создавался от root, при первом запуске
после обновления зарегистрируйте контейнер командой `docker compose up -d --build` —
права будут исправлены автоматически.

Срок хранения проверок и инцидентов настраивается в интерфейсе. Старые сессии
удаляются автоматически.

## Настройки

Доступны администратору в интерфейсе:

- название проекта;
- интервал проверки и таймаут;
- время показа инцидента в карточке;
- срок хранения проверок и инцидентов;
- интервал SSL-проверки;
- публичная статус-страница;
- получатели Telegram;
- пользователи и роли.

## Служебные эндпоинты

- `GET /healthz` — состояние базы и цикла мониторинга. Возвращает `200` при норме,
  `503` при деградации.
- `GET /status` — публичная статус-страница.
- `GET /api/public/status` — данные публичной страницы.

```
├── static/

│   ├── status.js         # Публичная страница
│   ├── style.css         # Стили и темы
│   └── vendor/           # Chart.js (MIT)
├── data/                 # SQLite, legacy-конфиг и логи (не в git)
├── .env.example

├── docker-compose.yml
└── requirements.txt
```
